## 关键决定

- 新建独立的 `getBuilding.ts` 而非改造 `getBuildingInfo.ts`：两者职责不同——getBuildingInfo 面向「展示建筑描述/位置」，getBuilding 面向「回答建筑属性问题（含 CHRS/FCI/RI）」。改造 getBuildingInfo 会混淆用途，新工具更清晰。
- bigram 相似度用于零命中建议（threshold 0.05）：轻量，不依赖 Levenshtein，足以找到近似名。
- `normalizeName` 去词尾列表经过权衡：去掉「lab/laboratory/hall/building」让「Hinds Lab」命中「Hinds Laboratory」；不去掉「kent」这类实意词。

- **修复 Subarea 作用域 bug（第四次同类复发）**
  - 根因：`query_campus_layer(layerName: 'subarea')` 无过滤入口，返回全部 14 个分区；agent 在文字里收窄到 B+C，但 mapUpdate 渲染全集
  - `queryCampusLayer.ts`：schema 加 `filterField?: string` + `filterValues?: string[]`，查询后按值过滤；return 里带上 `_mapFocus: { field, values }` 为将来兼容
  - `agent.ts`（结果处理）：加 `_mapFocus` 基础设施——若工具返回 `_mapFocus: { field, values }`，在设置 mapUpdate 前按字段/值过滤 FeatureCollection；case-insensitive；这是通用兜底，以后任何工具均可用
  - `agent.ts`（工具 spec）：`query_campus_layer` 加 `filterField`/`filterValues` 参数；subarea 说明改为「命名具体分区时必须传 filterField="SubArea" + filterValues=["B","C"]」
  - 部署：tsc 通过，esbuild 2.2MB，Lambda us-east-1 已更新
