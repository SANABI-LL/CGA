## Key Decisions

- **Resource-based policy as IAM workaround**: `AWSPowerUserAccess` blocks `iam:PutRolePolicy`. The Secrets Manager resource-based policy grants access to a specific principal without modifying the IAM role — consistent with the permission-wall workaround documented in CLAUDE.md.
- **New key never written to commit or chat**: Key generation and Secrets Manager write were done inside a Python `subprocess`, bypassing shell output. The user retrieves the new value from AWS Console → Secrets Manager to update `backend-config.local.js` locally.
