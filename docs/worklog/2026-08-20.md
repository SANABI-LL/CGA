### 待办 1：Session 对话历史存储（DynamoDB）

**问题**：用户追问"filter by 1890s"时后端无上下文，AI 回复"I don't have context"。

**方案**：复用现有 `campusgeo-queries-{stage}` 表（已有 `by-session` GSI），不新建表。每轮存 query / toolsUsed / featureCount / summary（前 150 字），TTL 4 小时自动过期。

**改动文件**：
- `backend/lambdas/ai-agent/session.ts`（新建）：`getSessionHistory` + `appendSessionTurn`，fail-silent（DynamoDB 不可用时返回空数组，不影响正常查询）
- `backend/lambdas/ai-agent/agent.ts`：`buildSystemPrompt(sessionHistory)` 注入历史上下文；`runCampusGeoAgent` 第 4 参数 `sessionHistory: SessionTurn[] = []`
- `backend/lambdas/ai-agent/handler.ts`：两个 handler（buffered + streaming）均加入 `getSessionHistory`（请求前）/ `appendSessionTurn`（响应后）；streaming handler 在 `metadata.end()` 之后 await 写入（不阻塞客户端收流）
- `backend/lambdas/ai-agent/package.json`：新增 `@aws-sdk/client-dynamodb ^3.717.0` + `@aws-sdk/lib-dynamodb ^3.717.0`
- `infra/cdk/stacks/ApiStack.ts`：`agentLambda` 加 `SESSIONS_TABLE` env var + `queryTable.grantReadWriteData(agentLambda)`

**验证**：`pnpm --filter @campusgeo/ai-agent typecheck` 通过；`handler.test.ts` 4 条全绿（tools.functional.test.ts 的 6 条失败为 pre-existing fixture 缺失，与本次无关）

## 关键决定

- **复用现有表而非新建**：`campusgeo-queries-prod` 已有 `by-session` GSI（`sessionId` PK + `timestamp` SK），完全满足需求，不新建表也不改 CDK DataStack
- **fail-silent 模式**：`getSessionHistory` 和 `appendSessionTurn` 都包裹在 try/catch，DynamoDB 权限未配时静默降级（不影响现有功能）
- **streaming handler 写时序**：`metadata.end()` 先于 `appendSessionTurn`，客户端接收到完整流后 Lambda 再写 DynamoDB，不引入延迟
- **system prompt 注入位置**：历史上下文插入 "Current year" 之后、"Guidelines" 之前，让模型在处理指令前先看到上下文

## 部署步骤

### 1. pnpm install（已完成）
```bash
pnpm install
```

### 2. 打包并部署 Lambda
```bash
cd backend/lambdas/ai-agent
pnpm dlx esbuild handler.ts --bundle --platform=node --target=node20 --format=esm \
  --outfile=dist/index.mjs --banner:js="import { createRequire } from 'module'; const require = createRequire(import.meta.url);"
cd dist && powershell -Command "Compress-Archive -Path index.mjs -DestinationPath lambda.zip -Force"
aws lambda update-function-code --function-name campusgeo-query --zip-file fileb://lambda.zip --profile GIS
aws lambda wait function-updated --function-name campusgeo-query --profile GIS
```

### 3. 手动加环境变量（CDK deploy 前的临时措施）
```bash
# 先读取当前全部 env（避免漏掉其他变量）
aws lambda get-function-configuration --function-name campusgeo-query \
  --query 'Environment.Variables' --profile GIS

# 加入 SESSIONS_TABLE，和现有变量一起更新（所有变量必须整组带全）
aws lambda update-function-configuration --function-name campusgeo-query \
  --environment 'Variables={GEOJSON_BUCKET=...,GEODATA_BUCKET=...,EMBED_MODEL_ID=...,BEDROCK_MODEL_ID=...,BEDROCK_REGION=us-east-2,BUFFERED=1,API_SECRET=...,ALLOWED_ORIGIN=...,SESSIONS_TABLE=campusgeo-queries-prod}' \
  --profile GIS
```

### 4. 加 IAM 权限（CDK deploy 前的临时措施）
```bash
# 查 Lambda execution role ARN
aws lambda get-function-configuration --function-name campusgeo-query \
  --query 'Role' --profile GIS

# 给 role 加 DynamoDB 读写权限（把 <account-id> 替换真实值）
aws iam put-role-policy --role-name <role-name> \
  --policy-name campusgeo-session-dynamo \
  --policy-document '{
    "Version":"2012-10-17",
    "Statement":[{
      "Effect":"Allow",
      "Action":["dynamodb:Query","dynamodb:PutItem","dynamodb:GetItem"],
      "Resource":[
        "arn:aws:dynamodb:us-east-1:<account-id>:table/campusgeo-queries-prod",
        "arn:aws:dynamodb:us-east-1:<account-id>:table/campusgeo-queries-prod/index/by-session"
      ]
    }]
  }' --profile GIS
```

### 5. CDK deploy（正式让 infra 和代码保持一致）
```bash
cd infra/cdk
npm run deploy:prod
```
